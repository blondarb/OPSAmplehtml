## Findings

### DEFECT FOUND POST-MERGE — fixed in `67c27f8` (deployed, re-verified on prod)

**Start was a dead button when only a referral was loaded.** The Start button's `disabled`
condition accepted a loaded referral, but `handleStartInterview`'s early-return guard did
not — so with a referral and no canned scenario the button rendered ENABLED and did nothing
on click. The referral-only path, the entire point of the feature, could not be started.

**Why this run missed it (the lesson):** these cases verified *"Start becomes enabled"* for
the referral path, and verified the consent gate via the **scenario** path. The two were
never combined. **Enabled is not the same as works** — a control that renders correctly can
still be inert. Any future entry-point case must click through to the next screen, not stop
at the button's disabled state.

Now covered by `tests/historian/startGuardParity.test.ts`, which asserts the handler guard
and the button condition name the same entry points; verified to fail with the bug restored.

**Other than that: no defects.** Zero regressions in the previously-verified consent-gate behavior.
