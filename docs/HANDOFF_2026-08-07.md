## The relay incident — caused by this session

CPU went **0.3% → 100% and never recovered** between 21:04 and 23:00. Cause: I ran 20+
WebSocket probes while bisecting the content filter, against a 0.25 vCPU task.

**Root cause of the leak is a real bug, still unfixed** (`services/nova-sonic-relay/src/server.ts`
~line 251). The stream-error handler logs and forwards the error but does **not** call
`session.stop()`:

```js
console.error('[nova-session] stream error:', message, err)
send(ws, { t: 'error', message })     // <- no session.stop(), no transcribe.stop()
```

Cleanup exists ONLY in `ws.on('close')`. So a normally-ended interview cleans up correctly; an
**errored** session leaks its Bedrock stream until the browser closes the socket.

## Nova vs OpenAI — the audio paths differ

Worth knowing, because it explains "it worked earlier and nothing changed in audio":

- **OpenAI** = WebRTC, `getUserMedia` → `pc.addTrack`. **Never touches an AudioContext.**
- **Nova** = `MicCapture` → **AudioContext** → worklet → downsample → base64 → WebSocket.

Making Nova the default moved every session onto the worklet path, which is the only one that
can suffer a suspended AudioContext. `?voice=openai` remains a clean escape hatch — it just
needs OpenAI credits.
