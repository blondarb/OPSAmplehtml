**R2 was a live production bug, not a hypothetical.** The wearables query succeeds and returns **0** unread alerts, so the old `total > 0` gate meant the dashboard displayed the hardcoded **"5 alerts, 2 urgent"** as a live clinical count. Verified against prod before and after; it now reads `0 — No unread alerts`. Every tile carries `dataSource`, and the UI fails safe: anything not explicitly `live` renders a "Sample data" marker.

**R5 has a rule attached** (`src/lib/logging/safeError.ts`): the audit's literal advice — "pass the caught error as a second argument" — is **unsafe on clinical paths**. node-postgres errors carry `detail`/`where`/`internalQuery`, and a constraint violation echoes the failing row values; on triage tables those are referral-derived, so a raw dump writes clinical text to CloudWatch. Use `describeError()` for any new catch on a PHI-adjacent path.

**R6 preserved the throwing form deliberately.** 3 of its 4 call sites are persisted-projection validation paths where a claimed-but-unreproducible mapper floor MUST fail closed; only the extract route moved to the non-throwing variant.
