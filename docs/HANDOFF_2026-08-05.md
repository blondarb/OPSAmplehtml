## Work Completed

### Made the simulated-patient safety gate honest

`tests/simulated-patients/runner.test.ts` is **the only test asserting that emergent cases triage correctly**. It had two failure modes that made it useless as a gate:

1. **No server running** — `beforeAll` threw, the file reported as one "failed file" everyone had learned to ignore, and the safety assertions never ran. It silently proved nothing.
2. **Server up but unauthenticated** — every call 401'd (`/api/triage/*` calls `authorizeClinicalAccess`; only the `/triage` **page** is in middleware `PUBLIC_ROUTES`). `result.data` came back falsy and cascaded into 6 alarming-but-meaningless failures:
   ```
   SAFETY: Emergent case "Acute Ischemic Stroke Presentation" was not triaged correctly: expected false to be true
   ```
   That reads like broken stroke triage. The request was simply rejected.

### Two additional blockers found while fixing it

Without these the fix would have been cosmetic — the suite **could not have gone green even fully authenticated**:

3. **`runTriage` never implemented the 202+poll pattern.** `POST /api/triage` returns `202 {session_id, status}` with no scores (SSE was reverted in PR #111 over the ~28s Amplify gateway timeout). The scored body only exists on `GET /api/triage/{id}` once `status === 'complete'`. Reading `triage_tier` off the POST body yields `undefined` → the *identical* SAFETY failure. The harness went stale when #111 landed and nobody noticed, because state 1/2 masked it.
4. **The auth cookie name was wrong.** `helpers.ts` sent `cognito-id-token`; the app reads `id_token` (`src/lib/cognito/server.ts`, `src/middleware.ts`). `TEST_EMAIL`/`TEST_PASSWORD` could never have authenticated anything.

### The three states, kept strictly apart

| State | Result | Why |
|---|---|---|
| Precondition unmet (not opted in, app down, no session, no clinical role) | **SKIP**, reason in the test name | Nothing clinical ran. An unmet precondition is not a safety failure. |
| Request rejected (401/403/503/5xx/network) | **FAIL**, `TRANSPORT (not a clinical result)` | The app refused the call. Nothing was graded. |
| 200 with a scored body | Clinical assertions + grading | The only state where a failure means the pipeline got something wrong. |

**The clinical assertions themselves are unchanged.** The fix makes the precondition explicit; it does not loosen what is checked.

## Known Risks / Watch Items

1. **The gate is honest, not yet proven.** It can no longer lie in either direction, but nobody has seen it go green. If the clinical assertions are themselves miscalibrated (wrong expected tiers in the personas, drifted red-flag strings), that will only surface on the first authenticated run.
2. **`TEST_SESSION_COOKIE` expires in 1 hour.** Cognito ID tokens are 1h. A ~14-minute run started near expiry will die mid-run — that now surfaces correctly as `TRANSPORT … HTTP 401`, not as a clinical failure, but it still wastes the run.
3. **The test account needs clinical access.** An active `clinical_access_memberships` row with role `clinician` or `admin` for the tenant, or preflight skips with a 403 reason. See memory `project_opsamplehtml_triage_membership_gate` — grants are manual SQL.
4. **Harness staleness is a recurring class of bug, not a one-off.** This harness silently rotted when PR #111 changed `/api/triage` to 202+poll, and the rot was invisible because the auth failure masked it. Any future change to the triage request/response contract can do the same.
5. `docs/amplify-static-compute-split` is still checked out with PR #174 open — unrelated to this session, but don't mistake it for this work.
